# PostgreSQL design for MovieMatch

## Поточні таблиці

- `users`: акаунти користувачів, email, ім'я та `password_digest`.
- `movies`: каталог фільмів і серіалів, TMDB id, `media_type`, назва, жанр, рейтинг, опис, постер, backdrop, trailer key, дата релізу, тривалість, режисер/автори, статус, бюджет, дохід, оригінальна мова та віковий рейтинг.
- `watchlists`: зв'язок many-to-many між користувачами та фільмами. У дипломі це можна описати як основне джерело персоналізації.
- `comments`: коментарі користувачів до конкретних фільмів або серіалів. Таблиця має зовнішні ключі `user_id` і `movie_id`.
- `ratings`: персональні оцінки користувачів. На відміну від `movies.rating`, який приходить із TMDB, `ratings.score` показує власну оцінку конкретного користувача.

## Що варто зберігати далі

- `user_movie_events`: події користувача (`view`, `search_click`, `add_to_watchlist`, `remove_from_watchlist`) з `user_id`, `movie_id`, `event_type`, `metadata jsonb`, `created_at`.
- `watch_providers`: джерела перегляду з `movie_id`, `provider_name`, `provider_url`, `country`, `access_type`. Це краще для диплома, ніж посилання на неофіційні сайти.
- `movie_genres`: окрема нормалізована таблиця жанрів, якщо один фільм матиме кілька жанрів.
- `recommendation_runs`: історія запусків алгоритму рекомендацій з `user_id`, `strategy`, `input_snapshot jsonb`, `created_at`.
- `recommendation_items`: конкретні рекомендовані фільми з `recommendation_run_id`, `movie_id`, `score`, `reason`.

## Чому PostgreSQL важливий для теми

PostgreSQL добре підходить для цього проєкту, бо дозволяє поєднати класичні реляційні зв'язки з аналітичними запитами. Для дипломної роботи можна показати:

- агрегацію вподобань користувача через `GROUP BY genre`;
- пошук за назвою, описом і режисером через `ILIKE`, а згодом через full-text search;
- збереження гнучких пояснень рекомендацій у `jsonb`;
- індекси для швидкого каталогу: `movies(genre)`, `movies(rating)`, `watchlists(user_id, movie_id)`;
- фільтрацію за `movies(media_type)`, щоб в одному каталозі підтримувати і фільми, і серіали;
- персональну аналітику через `ratings`, наприклад середню оцінку саме користувача, а не середній рейтинг інших глядачів;
- унікальне обмеження для захисту від дублювання фільмів у списку користувача.

## Приклад логіки рекомендацій

1. Знайти жанри, які користувач найчастіше додає у watchlist.
2. Відібрати фільми цих жанрів, яких ще немає у watchlist.
3. Відсортувати їх за рейтингом або комбінованим балом.
4. Зберегти результат у `recommendation_runs` і `recommendation_items`, щоб можна було аналізувати якість рекомендацій.
